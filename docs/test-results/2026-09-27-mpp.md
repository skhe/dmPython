# Real DM8 MPP login and distributed decimal regression (2026-09-27)

An isolated two-node DM8 MPP cluster ran in local Orb with the 2025-09-24
ARM image. Each node had a separately initialized database (`EP01`, `EP02`),
matching database creation parameters, `MAL_INI=1`, `MPP_INI=1`, a shared
`dmmal.ini`, and the same `dmmpp.ctl` generated from `dmmpp.ini`. Both nodes
reached `SYSTEM IS READY`, and their logs showed MAL links to each other.
This follows the [DM MPP configuration model](https://eco.dameng.com/document/dm/zh-cn/pm/basic-concepts-principles.html).

The ARM macOS Python 3.10 extension connected to both endpoints with
`mpp_login=DSQL_MPP_LOGIN_GLOBAL` and `mpp_login=DSQL_MPP_LOGIN_LOCAL`.
`scripts/verify_dm_mpp.py` created a hash-distributed table, batch-inserted
12 `DECIMAL(30,8)` rows, and checked the exact values from both endpoints.
The values included a 20-digit integer part with eight fractional digits,
negative values, and `0.00000001`.

| Query | EP01 endpoint | EP02 endpoint |
| --- | ---: | ---: |
| Global login | 12 exact rows | 12 exact rows |
| Local login | 6 exact rows | 6 exact rows |

The two local row ID sets were disjoint and their union equaled the 12 global
rows, proving that the test exercised both physical EPs. The script removed
its test table after success. It takes `DM_MPP_USER`, `DM_MPP_PASSWORD`,
`DM_MPP_EP1_HOST`, and `DM_MPP_EP2_HOST`; optional endpoint ports default to
5236. The account needs permission to create and drop a distributed table.

The test was run locally because GitHub-hosted runners cannot reach the Orb
cluster. The existing CI matrix uses one DM8 instance and does not exercise
MPP. This result covers a two-EP cluster and one DM8 server build; larger
clusters and MPP primary/standby combinations remain untested.
